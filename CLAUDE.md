# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Spring Boot 3.3.2 / Java 21 backend for Nimbus, an e-commerce store selling shoes (produtos with categorias, tipos, and size grades). Package root: `com.nimbus.nimbusWebServer`.

## Commands

```bash
./mvnw compile              # compile
./mvnw test                 # run all tests
./mvnw test -Dtest=ClassName#methodName   # run a single test
./mvnw spring-boot:run       # run locally (defaults to the "local" profile)
./mvnw clean package -DskipTests   # build the jar (as used by Dockerfile)
```

The active profile is controlled by `spring.profiles.active` in `application.properties`, defaulting to `local` (`application-local.properties`) unless `SPRING_PROFILES_ACTIVE` is set. Production config lives in `application-prod.properties` and pulls secrets from env vars.

- Local profile uses `spring.jpa.hibernate.ddl-auto=update` — schema changes to `@Entity` classes apply automatically on startup.
- Prod profile uses `ddl-auto=none` — any new/changed entity column needs a manual `ALTER TABLE` against the Supabase/Postgres database before deploying.

## Architecture

Standard layered structure per domain area (`controllers` → `services` → `repositories` → `models`), plus `dtos` and `mapper` for request/response shaping. Domain packages: `produtos`, `pedido`, `user`, plus top-level entities like `Carrinho`, `RefreshToken`, `SkuSequence`.

### Auth flow
- JWT-based, stateless (`spring.security` with `SessionCreationPolicy.STATELESS`).
- The access token is issued by `AccessTokenService` (HMAC256, 2h expiry, subject = user email) and delivered/read as an `accessToken` **cookie** (not an `Authorization` header) — see `UserAuthenticationFilter.recoveryToken`.
- `UserAuthenticationFilter` (a `OncePerRequestFilter`) runs before `UsernamePasswordAuthenticationFilter`, resolves the cookie, loads the `User`, and populates `SecurityContextHolder` for every request whose URI isn't in `SecurityConfig.ENDPOINTS_WITH_AUTHENTICATION_NOT_REQUIRED`.
- `SecurityConfig` centralizes route authorization in four static arrays: `ENDPOINTS_WITH_AUTHENTICATION_NOT_REQUIRED`, `ENDPOINTS_WITH_AUTHENTICATION_REQUIRED`, `ENDPOINTS_CUSTOMER` (role `ROLE_CUSTOMER`), `ENDPOINTS_ADMIN` (role `ROLE_ADMINISTRATOR`). **Any new controller route must be added to the correct array(s) here or it will 403/404 by default** (`anyRequest().denyAll()` is the fallback).
- There's also a `RefreshToken` entity/service for refresh-token rotation, separate from the short-lived access token.

### Produto domain
- `Produto` has a `@ManyToOne Categoria` and `@ManyToOne Tipo`, a `@OneToMany List<ImagemProduto> imagens` (ordered by an embedded `ImagemId(produtoId, sequencia)` — sequência 1 is the "imagem de apresentação"), and a `@OneToMany List<Grade> grade` (size options, embedded id `GradeId(produtoId, numeracao)`).
- `slug` is auto-generated in `@PrePersist` from tipo + categoria + nome (normalized, accents stripped, lowercased, hyphenated) — never set it manually via DTOs.
- `sku` is generated by `ProdutoService.gerarProdutoSKU`, combining `Tipo.abreviacao` + `Categoria.abreviacao` through `SkuSequenceService` (a persistent per-key counter in `SkuSequence`).
- `ProdutoResponseDto` is shared by both the list endpoint (`buscar_produtos`) and the detail endpoint (`obter_produto_por_slug`) via `ProdutoMapper` — changes to the mapper affect both.
- Business-rule constants that aren't (yet) per-product data — e.g. max installment count, delivery lead time — are configured globally via `@Value` properties (`nimbus.*` keys in `application-*.properties`), not as DB columns, unless a product-specific override is actually needed.
- Per-size stock tracking (estoque por grade) does not exist yet; `Estoque` only tracks one total quantity per product. Treat any "stock per grade" field as a placeholder until that feature lands.

### Image storage
- `StorageService` is an interface with two implementations: `ClouinaryStorageService` (`@Primary`, uploads to Cloudinary under `nimbus/produtos`) and `LocalStorageService` (writes to `./uploads`, used for local file serving via `/uploads/**`). Because Cloudinary is `@Primary`, it's the one actually injected unless explicitly qualified otherwise.

### Payments
- `PagamentoController` → `PedidoService.processarPagamento` → `MercadoPagoService` (Mercado Pago Java SDK). Checkout is idempotent: `PedidoService` looks up an existing `Pedido` by `idempotencyKey` before creating a new one, and falls back to the same lookup on `DataIntegrityViolationException` (race on concurrent duplicate requests).
- `installments`/`parcelas` is a per-order value supplied by the client at checkout (`CheckoutRequestDto`), not product metadata.

### Error handling
- `GlobalExceptionHandler` (`@RestControllerAdvice`) maps custom exceptions (`FileStorageException`, `FileNotFoundException`, `RecursoNaoEncontradoException`, `TokenExpiradoException`, etc.) to HTTP statuses, with a catch-all `Exception` handler returning 500. Prefer throwing/adding a custom exception here over ad hoc `ResponseEntity` error building in controllers/services.
